# Review fixes, production screens: test changes

Every assertion changed by the review fixes to `ui/modules/production/*` (Campaigns list, Users and
Schedules row actions, the empty Schedules screen, the Audit log), and why. Only one existing test was
rewritten, because one behaviour changed on purpose: the signed-in person's own row no longer offers
Disable. Nothing was loosened. The two-step confirm, the PATCH body and token, and the server's
`LAST_ADMIN` sentence are all still asserted. Every other change below adds assertions.

| File | Test | Old | New | Why |
|---|---|---|---|---|
| `tests/integration/production/ui/flow.test.mjs` | `the Users screen lists everyone, and the last Admin cannot be disabled` (renamed `the Users screen lists everyone; Disable is quiet red and asks twice; the last Admin cannot be demoted`) | Clicks `[data-toggle="disable"]` on the first row (admin-person, "(you)"); the confirm reads "Disable admin-person and sign them out?"; "Yes, disable" sends `PATCH {disabled: true}` and gets `409 LAST_ADMIN` ("This is the last active Admin.") | The own row (`ids.admin`) has **no** `[data-toggle="disable"]` but still has Change roles. Disable on viewer-person's row has exactly the classes `btn quiet sm pb-quiet-bad`. The first click sends nothing. The confirm reads "Disable viewer-person and sign them out?" and its "Yes, disable" is `.danger.confirm`. It sends `PATCH /users/<viewer> {disabled: true}` with the token, and the row says "Disabled and signed out.". The `LAST_ADMIN` refusal comes from Change roles on the own row (Admin unticked, Viewer ticked). That sends `PATCH /users/<admin> {roles: ["viewer"]}` with the token, and the screen shows "This is the last active Admin." | Disable is hidden on your own row, so the last Admin's refusal is now reached by demoting yourself. The server refuses that with the same `LAST_ADMIN` code (DEC-712). Disable is now a quiet button in `--bad` text; only the confirm step is filled red. |
| `tests/integration/production/ui/flow.test.mjs` | (fake API, same test) | `PATCH /users/{id}` always answered `409` `last_admin` | It answers from real fixtures: a roles change gets `409` `last_admin_demote`, disabling the Admin gets `409` `last_admin`, and disabling anyone else gets `200` `user_disabled` | The fake answers each request the way the real app does. The two new fixtures are captured in `test_production_ui_js.py` (see below). |
