# Data Doctor 🩺

**Plan:** [`plans/MARKETING_AI_PLAN_L_DATA_DOCTOR.md`](plans/MARKETING_AI_PLAN_L_DATA_DOCTOR.md) (M150–M161).
**Decisions:** DEC-1500 … DEC-1599 in [`DECISIONS.md`](DECISIONS.md).

Data Doctor is for people who do not have a data team. You bring the files you have, in the shape they come
out of your systems, and Data Doctor reads them the way a careful colleague would. This page says what it does
today, in plain words, and what it will not do.

Three promises hold everywhere:

- **Your file is never changed.** When Data Doctor reads a file differently from how it arrived, the file as
  it arrived is kept beside the one it reads (`original.csv` or `original.xlsx`).
- **It always says what it did.** A box under the file lists every change, with the numbers.
- **You can always say no.** **Read it as it is instead** reads the file exactly as it arrived.

---

## 1. Reading a file (intake, M150)

Intake runs on every file: an upload, a table or file imported from a connection, a raw table for *Build from
raw tables*, and next month's file for scoring. It runs the same rules every time, so next month's export is
read the same way as this month's.

| Your file has… | Data Doctor… |
|---|---|
| An Excel workbook (`.xlsx`, `.xlsm`) | Reads the sheet that holds a table (the biggest one, if there are several) and tells you which other sheets have tables, with a button to read one of those instead. Hidden sheets are read only when you name them. |
| A title, a date line or blank rows above the column names | Skips them and says on which row it found the names. |
| Two rows of column names (`Q1` above `Revenue`, `Units`) | Joins them: `Q1 Revenue`, `Q1 Units`. |
| The same column name twice | Numbers the second one: `spend`, `spend_2`. |
| A "Grand Total", "Sub-total" or a note ("Generated by CRM on 3 Oct") at the end | Leaves those rows out and shows their first cell. |
| Rows where every cell is empty | Leaves them out and counts them. |
| `-`, `unknown`, `not known`, `#DIV/0!` in a column of numbers or dates | Reads them as empty, so the column is numbers again. In a text column they stay as written: "Unknown" can be a real answer. |
| Columns with no name and nothing in them | Leaves them out. A column with no name but with values is kept as `Unnamed: 3`. |

What it leaves alone: a file whose first row already looks like column names keeps it, a total word that is
not a whole cell ("Total Care" is a plan name) is data, and a one-cell row at the end is a note only when it
has three or more words or a colon. A clean CSV is stored and read byte for byte as before.

**Old Excel files** (`.xls`, `.xlsb`) cannot be read: open them in Excel and save as `.xlsx` or CSV.
**Password-protected** workbooks cannot be read either.

The words and limits are in [`configs/intake.yaml`](../configs/intake.yaml): which words mean "no value",
which mean "total", how far down to look for the column names, how many rows may be left out at the end.

### For developers

- `engine/intake/grid.py` — the rules, on rows of text.
- `engine/intake/excel.py` — reading a workbook: the zip-bomb guard, cells to text.
- `engine/intake/run.py` — `intake_file`: decide from the head and tail, rewrite only when a rule applies,
  write the report (`IntakeReport`, `engine/intake/contracts.py`).
- The API: `POST /uploads` and `POST /clients/{id}/sources` take `sheet` and `intake` form fields;
  `POST /connections/{id}/import` takes them in its body. Every response carries `intake`.
- The screens: `ui/modules/intake/notes.js`.
- The tests: `tests/unit/intake/` (including thirty files shaped like real exports, `bench.py`),
  `tests/integration/test_api_intake.py`, `tests/integration/test_intake_ui.py`.

## 2. What Data Doctor will not do

- **Match people across files with no shared key.** It can tidy keys (leading zeros, prefixes) and say how many
  match; it does not guess that "R. Sharma, Pune" is "Rahul Sharma".
- **Read scanned PDFs, photos or free-form documents** as tables.
- **Invent history.** It can build an outcome from events you recorded; it cannot create one from nothing.
- **Change your original file, or write code.** Every change is a step from a fixed list that our tested code runs.
