# M98 Hand-off: The Treat List and Business-Language Reasons (DEC-1308)

## 1. Summary

Milestone M98 implements the downloadable treat list and plain business-language reasons (Plan J, milestone M98, DEC-1308).

Until deep CRM/ESP integrations are deployed, the downloaded file **is** the operational hand-off between Marketing AI and the client's campaign execution systems (e.g. ESP, SMS aggregator, dialler). Previously, clients downloaded `scores.csv`, which only provided model scores, quantiles, and technical feature names (`reason_1..n`) that frontline agents and marketing managers found difficult to interpret.

M98 introduces:
1. **A pure builder (`engine/decide/treat_list.py`)**:
   - Assembles `treat_list.csv`, `treat_list.parquet`, and `treat_list_summary.json` directly from finished scoring run artefacts (`scores.parquet` / `scores.csv`, `run.json`, `holdout_assignment.parquet`, `row_explanations.parquet`, `ranking_choice.json`).
   - Completely decoupled from the scoring pipeline stages (zero stage imports, zero pipeline rebinds; `scores_csv_columns` in `engine/contracts.py` is frozen and unchanged).
   - Enforces key business invariants:
     - `treat == 1` implies `holdout != True` and `suppression_reason is None`.
     - Sleeping dogs ($\Delta p \le 0$) are never treated.
     - Missing inputs remain strictly `null` (missing holdout is `None`, not `False`; missing net value is `None`, not `0.0`; fewer than 3 features leaves remaining reasons `None`, not empty strings).
     - Parquet stores boolean flags (`bool`); CSV formats flags as `1`/`0` for standard tabular ingest.
2. **Business-language reason dictionary and vectorised mapper (`configs/decide/reasons.yaml`, `engine/decide/reasons.py`)**:
   - Maps feature names and direction/value thresholds to clear human phrases ("Spent less each month for 3 months", "Raised two complaints in 30 days").
   - Unmapped features retain existing explanation text.
   - All phrases pass `engine.pilot.plain.jargon_in` with zero jargon.
   - Linear scale: vectorised mapping processes 200,000 rows in ~0.048 seconds (~0.24 seconds projected for 1M rows).
3. **Row-level privacy and access controls**:
   - `treat_list.csv` and `treat_list.parquet` registered as row-level artefacts in `configs/privacy.yaml`, `engine/privacy/layout.py`, and `ROW_LEVEL_ARTEFACTS` in `api/access_policy.py`.
   - Served via `GET /runs/{run_id}/treat_list.csv` and generic artefact endpoint `GET /runs/{run_id}/artefacts/{name}`.
   - Access requires the Analyst role when authentication is enabled, with an audit log record emitted on read.
4. **Guided setup proposals (`engine/agent/recommend.py`)**:
   - `suggest_reason_phrases` suggests plain business phrases for newly detected unmapped features with `confidence=AgentConfidence.CHECK`.
5. **Output page UI (`ui/modules/decide/`)**:
   - Renders a Treat List summary card displaying treat, holdout, explore, and suppression counts, along with an explicit instruction note: "include treat = 1, exclude holdout = 1".
   - Provides a "Download treat list" button gated by role in `ui/modules/production/gate.js`.

## 5. Decision Text (DEC-1308)

### DEC-1308: The treat list and business-language reasons

**Context:**
Until deep integration with execution tools, the downloaded CSV/Parquet is the campaign hand-off. `scores.csv` was designed for technical monitoring; it carries model scores, quantiles, and technical feature names (`reason_1..n`) that frontline agents cannot explain to customers. Furthermore, downstream systems require explicit instructions on who to treat and who to exclude from holdout.

**Decisions:**
- **(a) Pure builder artefact:** A pure function `engine/decide/treat_list.py` builds `treat_list.csv`, `treat_list.parquet`, and `treat_list_summary.json` over a finished scoring run's existing artefacts. It does not touch frozen pipeline stages (`engine/stages/explain.py`, `engine/stages/export.py`), preserves `scores_csv_columns` in `engine/contracts.py`, and is generated lazily upon request or storage availability.
- **(b) Treat list schema and invariants:**
  - Columns: `customer_key` (composite keys supported), `use_case`, `model_version`, `band`/`segment`, `treat`, `holdout`, `explore`, `suppression_reason`, `offer`, `channel`, `net_value`, `reason_1`, `reason_2`, `reason_3`.
  - Invariants: `treat == 1` strictly requires `holdout != True` and `suppression_reason is None`; sleeping dogs are never treated. Missing inputs are `null` (not default `False` or `0.0`). Parquet writes `bool` types; CSV formats flags as `1`/`0`.
- **(c) Business reason dictionary:** `configs/decide/reasons.yaml` maps feature names and directions to plain business phrases containing zero jargon per `jargon_in`. Unmapped features keep their existing explanation strings. Vectorised mapping (`engine/decide/reasons.py`) scales linearly to 1M+ rows.
- **(d) Row-level privacy & access control:** Registered in `configs/privacy.yaml`, `engine/privacy/layout.py`, and `ROW_LEVEL_ARTEFACTS` in `api/access_policy.py`. Access requires Analyst role when authentication is enabled and is audited with `audit_reads=True`.
- **(e) Guided setup suggestions:** `engine/agent/recommend.py::suggest_reason_phrases` proposes plain phrase mappings for unmapped features with confidence `CHECK`.
- **(f) UI integration:** Output page shows Treat List summary card with explicit guidance ("include treat = 1, exclude holdout = 1") and a role-gated download button.

**Consequences:**
Campaign managers can immediately export ready-to-execute lists with clear business justifications and unambiguous treatment boundaries.
