## 1. Summary

Milestone M98 implements the downloadable treat list and plain business-language reasons (Plan J, milestone M98, DEC-1308).

Until deep CRM/ESP integrations are deployed, the downloaded file **is** the operational hand-off between Marketing AI and the client's campaign execution systems (e.g. ESP, SMS aggregator, dialler). Previously, clients downloaded `scores.csv` (the "contact list"), which only provided model scores, quantiles, and technical feature names (`reason_1..n`) that frontline agents and marketing managers found difficult to interpret.

M98 introduces:
1. **A pure builder (`engine/decide/treat_list.py`)**:
   - Assembles `treat_list.csv`, `treat_list.parquet`, and `treat_list_summary.json` directly from finished scoring run artefacts (`scores.parquet` / `scores.csv`, `run.json`, `run_config.json`, `holdout_assignment.parquet`, `row_explanations.parquet`, `expected_gross_value.json` and the uploaded rows).
   - Completely decoupled from the scoring pipeline stages (the pipeline and the stages never import it; no pipeline rebind; `scores_csv_columns` in `engine/contracts.py` is frozen and unchanged).
   - Enforces key business invariants:
     - `treat == 1` implies `holdout != True`, `suppression_reason is None` and not a sleeping dog.
     - Missing inputs remain strictly `null` (missing holdout is `None`, not `False`; missing net value is `None`, not `0.0`; fewer than 3 features leaves remaining reasons `None`, not empty strings).
     - Parquet stores boolean flags (`bool`); CSV formats flags as `1`/`0` (empty when null).
   - **Claude Code fix:** every per-customer file is joined to the scores on **all** key columns, never by position (holdout, explore, `treated`, reasons); a customer a file does not cover gets null. `treat` is M92's `treated` column (or M92's own `selection_masks` / `treated_flags` where there is none). The run's own `run_config.json` is read, not today's use case file. A propensity run's money is `expected_gross_value` (not incremental) and its `net_value` stays null; an uplift run's `net_value` is M97's column. Details: `docs/DECIDE.md` §12.
2. **Business-language reason dictionary and vectorised mapper (`configs/decide/reasons.yaml`, `engine/decide/reasons.py`)**:
   - **Claude Code fix:** phrases are keyed by feature and by direction, where the direction is the effect on the **score** (`Reason.direction`), not the movement of the customer's value. A phrase prints the row's own `{value}` and says which way it moved the score ("Monthly spend of 1499 pushes the score down"); it asserts no trend and no number of its own (the file is refused when it loads if a phrase holds a digit outside `{value}`). The partner's phrases ("Spent less each month for 3 months", "Raised two complaints in 30 days") stated things no row carries and are gone.
   - Unmapped features, directions with no phrase, and reasons whose value is missing retain existing explanation text.
   - All phrases pass `engine.pilot.plain.jargon_in` with zero jargon.
   - Linear scale: the mapping of 200,000 reasons takes about 0.2 s (about 1 s for 1M); the whole build is in §3.
3. **Row-level privacy and access controls**:
   - `treat_list.csv` and `treat_list.parquet` registered as row-level artefacts in `configs/privacy.yaml`, `engine/privacy/layout.py`, and `ROW_LEVEL_ARTEFACTS` in `api/access_policy.py`.
   - Served via `GET /runs/{run_id}/treat_list.csv` and generic artefact endpoint `GET /runs/{run_id}/artefacts/{name}`.
   - Access requires the Analyst role when authentication is enabled, with an audit log record emitted on read. `tests/integration/decide/test_row_level_downloads.py` is **untouched**: it covers the new files by itself, because it walks `ROW_LEVEL_ARTEFACTS`.
   - **Claude Code fix:** a run that cannot have a treat list answers `409 RUN_NOT_SCORED` with the reason in plain words (it was swallowed at debug level and the user read "There is no artefact called treat_list.csv"). A file already stored is served as it is.
4. **Guided setup (`engine/agent/recommend.py`, `engine/agent/advisor.py`)**:
   - `suggest_reason_phrases` suggests plain business phrases for columns `reasons.yaml` does not cover, with `confidence=AgentConfidence.CHECK`.
   - **Claude Code fix:** Guided setup now calls it, and lists the wording among the helper's **assumptions**, not as a setting: no run setting can hold a phrase, so a ticked "setting" would have applied nothing. The suggested phrases are in the same form as `reasons.yaml` (feature, `{value}`, the score moved up or down); the partner's "Higher x" / "Lower x" said the value was higher or lower, which is the direction error of the review's first finding. The agent benchmark's golden digest lists proposals only, so `tests/fixtures/agent_bench/expected.json` is unchanged (`--update` rewrote it with an empty diff).
5. **Output page UI (`ui/modules/decide/`)**:
   - Renders a Treat List summary card displaying treat, holdout, explore, and suppression counts, along with an explicit instruction note: "Include treat = 1, exclude holdout = 1."
   - Provides a "Download treat list (CSV)" button gated by role in `ui/modules/production/gate.js`.
   - **Claude Code fix:** the card read fields the summary does not have (it would have drawn zeros) and drew nothing when the summary failed to load. It now reads `total_rows`, `treat_rows`, ... and shows the server's message on failure. It also tells the two downloads apart: the Output page's "Download contact list (CSV)" is `scores.csv`; the card's "Download treat list (CSV)" is `treat_list.csv`. `tests/integration/uplift/test_uplift_browser.py` saves the contact list under the local file name `treat_list.csv`; that is the test's own name for a file on disk (the browser names the download after the URL, `scores.csv`), the product never serves `scores.csv` under that name, and the Phase 3b test is left as it is.

## 5. Decision Text (DEC-1308)

### DEC-1308: The treat list and business-language reasons

**Context:**
Until deep integration with execution tools, the downloaded CSV/Parquet is the campaign hand-off. `scores.csv` was designed for technical monitoring; it carries model scores, quantiles, and technical feature names (`reason_1..n`) that frontline agents cannot explain to customers. Furthermore, downstream systems require explicit instructions on who to treat and who to exclude from holdout.

**Decisions:** (the partner's (a)-(f), corrected, and one item per fix that changes behaviour)
- **(a) Pure builder artefact:** A pure function `engine/decide/treat_list.py` builds `treat_list.csv`, `treat_list.parquet`, and `treat_list_summary.json` over a finished scoring run's existing artefacts, on first request. It does not touch frozen pipeline stages (`engine/stages/explain.py`, `engine/stages/export.py`), preserves `scores_csv_columns` in `engine/contracts.py`, and changes no existing file of the run.
- **(b) Treat list schema and invariants:**
  - Columns: key columns (composite keys supported), `use_case`, `model_version`, `band`/`segment`, `treat`, `holdout`, `explore`, `suppression_reason`, `offer`, `channel`, `net_value`, `expected_gross_value`, `reason_1`, `reason_2`, `reason_3`.
  - Invariants: `treat == 1` strictly requires `holdout != True`, `suppression_reason is None` and not a sleeping dog. Missing inputs are `null` (not default `False` or `0.0`). Parquet writes `bool` types; CSV formats flags as `1`/`0`, empty when null.
- **(c) Business reason dictionary:** `configs/decide/reasons.yaml` maps a feature and a direction to a plain phrase. The direction is the effect on the score; a phrase prints the row's own `{value}` and says which way it moved the score, and holds no number or trend of its own (refused on load). Phrases contain zero jargon per `jargon_in`. Unmapped features, unmapped directions and missing values keep their existing explanation strings. Vectorised mapping (`engine/decide/reasons.py`) scales linearly to 1M+ rows.
- **(d) Row-level privacy & access control:** Registered in `configs/privacy.yaml`, `engine/privacy/layout.py`, and `ROW_LEVEL_ARTEFACTS` in `api/access_policy.py`. Access requires Analyst role when authentication is enabled and is audited with `audit_reads=True`.
- **(e) Guided setup suggestions:** `engine/agent/recommend.py::suggest_reason_phrases` proposes phrase wording for columns `reasons.yaml` does not cover, with confidence `CHECK`. Guided setup lists it among the helper's assumptions: no run setting can hold a phrase, so nothing is ticked or applied.
- **(f) UI integration:** Output page shows the treat list card with the counts, the guidance ("Include treat = 1, exclude holdout = 1"), the server's message when the summary cannot load, and a role-gated "Download treat list (CSV)" button, labelled apart from the page's "Download contact list (CSV)" (`scores.csv`).
- **(g) Join on the key (finding 2):** every per-customer file (`holdout_assignment.parquet`, `row_explanations.parquet`, the upload) is joined to the scores on all key columns, never by position. A customer a file does not cover is null (holdout and explore) or keeps `scores.csv`'s text (reasons), never false. A file that repeats a key is not guessed at.
- **(h) Read, do not recompute (finding 3):** `treat` is M92's `treated` column; without it, M92's own `selection_masks` and `treated_flags` (now public in `engine/holdout/assign.py`).
- **(i) One unit per column (finding 4):** `net_value` is M97's incremental net value (uplift runs); a propensity run's expected gross value is its own column `expected_gross_value`, labelled "not incremental"; both in rupees to the paisa; `net_value` is null on a propensity run.
- **(j) The run's own settings (finding 5):** the builder reads `run_config.json`; a run without one is refused with a plain reason, not read from today's file.
- **(k) Plain refusal:** a run that cannot have a treat list answers `409 RUN_NOT_SCORED` with the reason; no exception is swallowed.
- **(l) Offer follows treat:** `offer` is null for a control row; an explored customer gets the uplift policy's treat action on an uplift run and no offer on a propensity run, so no row says `treat = 1` beside "Hold".

**Consequences:**
Campaign managers can immediately export ready-to-execute lists with clear business justifications and unambiguous treatment boundaries, and the reasons they read are true of the customer they are printed for.

## 7. Open Questions and Known Gaps

1. **`scripts/bench_1m.py` unreachable warning on macOS:**
   - In `scripts/bench_1m.py` (created in M54), `if sys.platform == "darwin":` has unconditional returns in both try/except blocks. On macOS, `mypy --strict --warn-unreachable` flags lines 53 and 69 as unreachable. On Linux (the CI environment), it passes cleanly. Per §4.7 Rule 6 ("Stay in your lane; no drive-by fixes in other workstreams' files"), this file was left untouched and is raised here for review. Review answer: it is a known macOS-only mypy quirk; leave the file as it is.
2. **Channel and offer placeholders:**
   - As specified in Plan J M98, `offer` defaults to the band's action (or null when suppressed or held out) and `channel` defaults to null. These nullable columns will be populated by M99 (Catalogue) and M100 (Multi-treatment uplift). Until then an explored customer on a **propensity** run has no offer: the bands name none for a band the list does not contact.
3. **Wording in Guided setup cannot be applied yet.** A phrase has no run setting to live in. The helper lists suggested wording for `configs/decide/reasons.yaml` among its assumptions; a person adds it. A per-client dictionary would be a later milestone.
4. **`reasons.yaml` cannot name a window in digits.** A phrase may hold no number outside `{value}`, so features named for a window (`visits_last_7d`, `ad_ctr_90d`) are described as "the latest week", "recent months". Adding a feature whose name carries a digit means wording it without one.
5. **A treat list is built once.** Editing `reasons.yaml` later does not change a finished run's file (runs are immutable); delete the three `treat_list*` files of a run to rebuild it.
6. **The browser test's local file name.** `tests/integration/uplift/test_uplift_browser.py` (Phase 3b) saves the contact list as `treat_list.csv` on disk. Renaming that local file to `contact_list.csv` would remove the coincidence; it was not done here (not Plan J's file, and the browser test cannot run in this environment).
7. **Timing.** About 13 to 16 s per million customers on this machine (§3). Most of it is writing a 250 MB CSV (the parquet is 38 MB and takes under a second).
