## 1. Summary

Milestone M97 implements net-value-based customer ranking and policy selection for uplift and propensity runs (Plan J, milestone M97). Instead of ranking solely by raw uplift $\Delta p = p_{\text{treat}} - p_{\text{control}}$, the decision policy now ranks and budgets contacts by expected net financial value:

$$\text{Net value per customer} = \Delta \times \text{value} \times \text{margin} - \text{offer\_cost} \times p_{\text{treated}} - \text{contact\_cost}$$

Key capabilities delivered:
- **Value-weighted policy configuration**: `UpliftPolicyConfig` gains optional fields `value_column`, `horizon_months`, `margin_pct`, and `min_roi`, all agent-editable.
- **Configurable cost defaults**: Configured via `configs/pilot/value.yaml` with editable India defaults (`whatsapp: 0.86`, `whatsapp_marketing: 0.86`, `whatsapp_utility: 0.13`, `sms: 0.15`, `email: 0.05`, `voice: 0.70`, `offer_cost: 0.0`), accessed via `engine.pilot.roi.lookup_value_costs`.
- **Ranking and policy optimization**: `engine/uplift/policy.py` (`ranking`, `choose_contacts`, `recommend_policy`, `profit_curve`) evaluates the net value vector. Customers with net value below cost or failing `min_roi` are excluded. Crucially, the mathematical identity between the profit curve point at budget and the policy recommendation holds strictly. Persuadable-only and sleeping-dog guards ($\Delta \le 0$) remain inviolable.
- **Value-weighted holdout evaluation**: The training holdout parquet file carries the `"value"` column (*Review:* only when the training run sets `value_column`, as `HOLDOUT_VALUE_COLUMN` after an unchanged `HOLDOUT_COLUMNS`), enabling `HoldoutUplift` in `engine/uplift/metrics.py` to compute observed uplift weighted by customer value.
- **Propensity gross value tracking**: Scoring runs compute `expected_gross_value` per row ($p \times \text{value} - \text{cost}$), labelled explicitly as `"not incremental"` everywhere it appears. (*Review:* moved to `engine/decide/value.py`, propensity score flow only, written to `expected_gross_value.json`; `apply_actions` and `scores.csv` unchanged.)
- **Guided setup recommendations**: `engine/agent/recommend.py` proposes value-like candidate columns (`order_value`, `premium`, `balance`, `arpu`) with `AgentConfidence.CHECK`.
- **API & UI contracts**: `ProfitCurve` exposes `value_weighted` and `value_basis`; `PolicyRecommendation` exposes `net_value_low` and `net_value_high`; `GET /runs/{id}/uplift/profit-curve` supports query parameters `min_roi` and `value`. The UI `profitCard` renders `value_basis`.

```markdown
## DEC-1310 — Net-value ranking for uplift and propensity policies (Plan J M97)

### (a) Context
Uplift modeling ranks contacts by predicted conversion uplift $\Delta p = p(\text{treat}) - p(\text{control})$. However, in commercial campaigns, customer values differ by orders of magnitude (e.g. ₹5,000 order value vs ₹150). Targeting customers by uplift alone prioritizes high-probability small purchasers over slightly lower-probability high-value purchasers, sacrificing substantial incremental revenue. Furthermore, outbound campaigns incur direct contact costs (SMS, WhatsApp, Voice) and offer incentives that must be subtracted to establish true incremental net profit.

### (b) Decision
1. Extend `UpliftPolicyConfig` with optional `value_column: str | None`, `horizon_months: int = 1`, `margin_pct: float = 100.0`, and `min_roi: float | None`.
2. Compute net value per customer as:
   $$\text{net\_value}_i = \Delta p_i \times \text{value}_i \times \frac{\text{margin\_pct}}{100} - \text{offer\_cost} \times p(\text{treat})_i - \text{contact\_cost}$$
3. Rank customers by net value vector in `engine/uplift/policy.py`. Filter contacts whose net value is negative or below the `min_roi` hurdle. Maintain strict guards: customers with $\Delta p \le 0$ (sleeping dogs) are never targeted.
4. Provide editable defaults in `configs/pilot/value.yaml` covering Indian channel contact costs (`whatsapp: 0.86`, `whatsapp_marketing: 0.86`, `whatsapp_utility: 0.13`, `sms: 0.15`, `email: 0.05`, `voice: 0.70`, `offer_cost: 0.0`), resolved via `engine.pilot.roi.lookup_value_costs`.
5. Retain `"value"` in training holdout parquet files (`HOLDOUT_COLUMNS`) so observed holdout uplifts can be value-weighted.
6. In propensity runs, compute `expected_gross_value` ($p \times \text{value} - \text{cost}$) labeled `"not incremental"`.

### (c) Consequences
- Campaigns maximize bottom-line profit rather than raw conversion count.
- The mathematical identity between the profit curve point at budget and the policy recommendation holds whether or not a `value_column` is configured.
- When `value_column` is omitted, behavior matches the scalar `value_per_conversion` path identically.
- M99's upcoming Action Catalogue will integrate with `lookup_value_costs` seamlessly.
```
