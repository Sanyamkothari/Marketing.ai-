DESIGN DIRECTION (decided; implement it, do not re-decide):
1. TYPE. Ship Inter Variable (OFL-1.1) with the app: `npm pack @fontsource-variable/inter@5.3.0` (registry.npmjs.org is reachable), copy the latin + latin-ext woff2 files and the OFL licence into ui/fonts/inter/, an @font-face with font-display:swap. Scale: page title 28/36 semibold (600), section title 18/26 600, card title 15/22 600, body 14/22 400, small 13/20, caption 12/16 muted. Hero figure ≥48px 600 proportional figures; numbers in table columns use tabular figures (font-variant-numeric: tabular-nums); stat-tile values proportional.
2. COLOUR. Primary = var(--brand-blue) (#1E57BD by default; M182 lets a deployment change it, so every brand-coloured thing derives from that variable, tints via color-mix(in srgb, var(--brand-blue) N%, white) with a fallback). Primary buttons, active navigation, links, focus rings, selected states are brand blue — not black. Neutrals: keep the existing cool greys (--ink #111827 … --line #E5E7EB, canvas #F5F6F8). STATUS colours are reserved for meaning and always come with an icon AND a word (never colour alone): good #15803D on #E8F6EE, warning #B45309 on #FEF3C7, critical #B42318 on #FDECEC, info = brand tint, neutral grey. Map: campaign status Measured = good, Live = info (brand), Waiting for results = warning, Draft = neutral; evidence labels Proven = good, Estimated = info, Not yet proven = neutral; data health "Read correctly" = good, problems = warning/critical. Charts and ramps: keep the validated blue ramp already in --bs0…--bs4; do not invent chart colours.
3. LAYOUT. No page card: content sits directly on the canvas, max-width 1200px, page padding 32px desktop / 16px phone. Cards are white, radius 12px, a 1px #E5E7EB border OR a soft shadow (0 1px 2px rgba(16,24,40,.06), 0 1px 3px rgba(16,24,40,.10)) — choose ONE treatment for all cards and never nest a bordered card inside another card. 8px spacing scale (4, 8, 12, 16, 24, 32, 48). Page header: title + one-line subtitle on the left, the page's ONE primary button on the right on desktop (below on phone); breadcrumbs only on pages below a top-level place (not on Overview, Campaigns, Data, Reports, Settings).
4. SHELL (campaigns layout). The product name and mark move to the top of the sidebar; the sidebar has the five places with icons (24px line icons, 1.75px stroke), active item = brand tint background + brand text + a 3px brand bar on the left; Minfy appears small at the sidebar foot ("by Minfy" + logo), not competing top right. Top bar: page context left, bell / Help / profile right, 56px tall, white with a bottom hairline. Phone: the sidebar becomes a drawer behind Menu (keep M174's behaviour and keyboard rules).
5. COMPONENTS (one implementation each, reused everywhere):
   - Buttons: primary (brand fill, white text), secondary (white, 1px line, ink text), tertiary (text, brand colour); heights 40 (default) / 32 (small); radius 8; icon + label allowed; disabled and busy states; focus ring brand 2px offset 2px.
   - Tabs: underline tabs (text, 2px brand underline on the selected tab, hover ink) — for the campaign page tabs, Reports tabs and Data tabs. Not pills.
   - Wizard stepper: numbered circles joined by a line; done = brand circle with a check; current = brand ring; upcoming = grey; labels under the circles; on phone show "Step 2 of 5 · Customers".
   - Chips / badges: 24px tall, radius 999, icon (12px) + word, status colours above. Neutral tag chips (e.g. goal stage "Win-back") are quiet grey outline.
   - Stat tile: label (13 muted, sentence case) · value (24–32px 600 proportional) · optional caption; a KPI row lays 2–4 tiles in a grid.
   - Value range: a number with its likely range drawn as a small horizontal interval bar (a track, the range as a brand bar with rounded 4px ends, a dot at the central estimate, a zero tick when the range is near zero), the words stay beside it ("Likely ₹88,187 to ₹4.18 lakh"). Pure SVG/HTML from figures the page already has; no new API. Text tokens for text, never the bar colour.
   - Tables: header 12px 600 muted uppercase-free, rows 52px min, row hover tint, numeric columns right-aligned tabular; a long explanation leaves the table: the table shows the number (and a value range), the explanation moves to a tooltip-free secondary line or the detail page. On phone, tables become stacked row cards.
   - Empty states: a 40px line icon, one sentence, one action.
   - Forms: inputs 40px, radius 8, 1px line, brand focus ring, labels above, help text below in muted.
   - Alerts / attention items: a coloured icon, title, one line, action button on the right on desktop and BELOW the text on phone (never a squeezed column).
   - Motion: 120–160ms ease for hover/press/drawer; none when prefers-reduced-motion.
6. Classic layout: it inherits the new tokens, font and components (shared CSS) and must keep working; its markup is not reworked. Dark mode is out of scope.
7. ACCESSIBILITY: every text/background pair ≥ 4.5:1 (3:1 for ≥18.66px bold / 24px), status never colour-alone, focus visible everywhere, hit targets ≥ 40px on touch, the existing accessibility/keyboard tests stay green and their known-defects lists may only shrink.
