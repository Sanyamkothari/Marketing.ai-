2. "The job of Data Doctor is to take input data and make it ready for the next step, which is AutoML." → Output = one model-ready dataset + a replayable prescription + a readiness report that GUARANTEES the run will not fail for data reasons (see 02: close the gaps where validation passes but split/train fails).

6. "There should be one generic Data Doctor as we have now and one in a particular use case that knows what we are trying to achieve." → DECIDED (main session): ONE agent with an optional GOAL BRIEF. Without a goal: understand files, fix general problems, say what the data can power (and what is missing for other goals). With a goal: the brief (from the use-case config: target, success definition, time rules, required columns — value, consent, channels — split, model types) drives goal-specific checks and questions and the readiness checklist for that goal. Seamless transition: start generic, pick a goal, continue without restarting (same case, memory, recipe).
7. "Is it able to handle new things, like we configured it for ₹ but the client is from the US and we get $ in the file?" → Today parse_number strips ₹/Rs/INR/$/US$/USD/€/EUR/£/GBP and only NOTES the symbol; the unit is lost downstream (net value/budgets/reports assume ₹); mixed ₹ and $ in one column would be merged without conversion. REQUIREMENTS: (a) money columns keep their currency as a recorded unit in the prescription; (b) workspace/client currency setting instead of hard-coded ₹ (UI already says "never invent a unit"); (c) a different currency than the workspace → ASK: report in that currency, or convert at a person-given dated rate (APPROVAL, rate recorded and shown in reports); (d) mixed currencies in one column → STOP and ASK which rows are which; never add them together; (e) a LOCALE PROFILE per client detected and confirmed once, remembered: currency, decimal mark, date order, number words (lakh/crore, K/M), phone/postcode/ID formats as PII (US SSN/ZIP vs India PAN/Aadhaar/PIN/GSTIN), time zone, consent regime (TRAI/DPDP vs CAN-SPAM/TCPA).

New abilities arrive as new tools without rebuilding the agent.
